## Что уже исправлено в этом коммите

1. **Импорт в админке** (`src/app/admin/(dash)/leads/[id]/page.tsx`):
   `'../../actions'` → `'../../../actions'`. Именно эта строка роняла деплой;
   подтверждено логом Vercel: `Module not found: Can't resolve '../../actions'`.
2. **Миграции**: сгенерированы (`drizzle/0000_sticky_wolfpack.sql`, 20 таблиц) и
   закоммичены. Раньше каталога не было — приложение стартовало без схемы.
3. **Ошибки типов**: экспортирован `LeadKind`, сужение `claim` в `claims.ts`,
   путь импорта в админке. `tsc --noEmit` — 0 ошибок.
4. **БД не требуется для сборки**: read-пути используют `tryGetDb()` и при
   недоступной БД отдают безопасное значение (пустой список/дефолт) вместо 500.
   Корневой layout помечен `force-dynamic`, чтобы меню и гейты страниц
   вычислялись на каждом запросе, а не «замораживались» на этапе сборки.
5. **Serverless-совместимость**: PGlite и локальное хранилище файлов
   переключаются на `/tmp` при `process.env.VERCEL`; `drizzle/**` включён в
   вывод через `outputFileTracingIncludes`.
6. **Шрифт**: переведён на `next/font` (self-hosting). Убрал блокирующий
   внешний stylesheet, который к тому же не проходил собственный CSP, и
   предупреждение `no-page-custom-font`.
7. **Lint**: `next-env.d.ts` (генерируется Next) добавлен в `ignores`.
8. **`SESSION_SECRET`** задан в Vercel (Production) — сгенерирован случайным.

Проверки после правок: `npm run lint` — чисто, `npm run build` — 38 маршрутов,
`npm run db:seed` — успешно.

## Что должен сделать владелец (без этого публиковать нельзя)

### 1. Постоянная БД — P0

Скрипт не может создать её за владельца. Нужен бесплатный Postgres (Neon,
Supabase или Railway), затем в Vercel → Settings → Environment Variables:

```
DATABASE_URL = <строка подключения с пулером>
```

Без неё приложение работает на встроенной PGlite в `/tmp`: файловая система
serverless-функции эфемерная, экземпляров несколько — **заявки будут
теряться**. Это прямое нарушение приоритета №1 проекта.

После добавления — применить схему и залить справочники:

```bash
npm run db:migrate
npm run db:seed
```

### 2. Владелец в админке — P1

```
ADMIN_BOOTSTRAP_EMAIL    = <email владельца>
ADMIN_BOOTSTRAP_PASSWORD = <временный пароль, сменить при первом входе>
```

Затем `npm run db:seed` создаёт владельца. Первый вход — со сменой пароля.

### 3. Доставка заявок — P1

Сейчас заявка сохранится, но менеджер о ней не узнает: Telegram не настроен.
Нужно в Vercel:

```
TELEGRAM_BOT_TOKEN        = <токен от @BotFather>
TELEGRAM_WEBHOOK_SECRET   = <случайная строка>
TELEGRAM_LEADS_CHAT_ID    = <id чата менеджеров>
TELEGRAM_OWNER_ID         = <id владельца, для эскалации>
NOTIFY_EMAIL_TO + RESEND_API_KEY  = резервный канал
```

Вебхук бота: `https://<домен>/api/telegram/webhook`.

### 4. Прочее

- `SITE_URL` — боевой домен (сейчас canonical/OG указывают на `localhost`).
- `CRON_SECRET` + расписание cron (см. `README`): без него не работают
  эскалация SLA, напоминания о замерах, дайджест и просьба об отзыве.
- Хранилище файлов: на Vercel `/tmp` эфемерен, для фото работ нужен S3/R2.
